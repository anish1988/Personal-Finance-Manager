# Epic 5 — Frontend & Statement Ingestion (Overview)

**Goal:** Allow users to upload monthly bank statements (Excel & PDF), ingest and standardize transactions into the DB, provide a review UI to confirm categories and corrections, and enable the analytics/AI layers to run on the consolidated data.

**Key features**

1. Frontend upload UI (bank name, account type, file upload, month selector).
2. Backend upload API + background processing pipeline for parsing (Excel & PDF).
3. Transaction normalization (columns → canonical fields).
4. Auto-categorization (rules + LLM fallback) and UPI/tags detection.
5. Human-in-the-loop review interface (approve/adjust categories, add comments).
6. Persist cleaned transactions to DB (linked to user + source metadata).
7. Trigger reports & AI insights automatically after ingestion.

# Architecture & Components (high level)

* **Frontend (React)**

  * Upload form & file list with statuses (uploaded, processing, needs_review, done).
  * Review UI: list of parsed transactions with suggested category, inline edit.
  * Progress/notifications and charts/dashboard integration.

* **Backend (FastAPI)**

  * `POST /uploads` — accepts multipart form (bank_name, account_type, statement_month, files[]).
  * `GET /uploads/{upload_id}` — status & preview.
  * `GET /uploads/{upload_id}/transactions` — preview parsed transactions (with suggested categories).
  * `POST /uploads/{upload_id}/confirm` — commit parsed transactions to DB.
  * `GET /uploads/{upload_id}/errors` — parsing errors.

* **Processing worker (background)**

  * Use **Celery + Redis** (or RQ) for background tasks, or simple FastAPI background tasks for low volume.
  * Tasks:

    * `parse_file(file_path, metadata)` → extract raw rows (pandas for Excel, Camelot/Tabula or pdfplumber/pdfminer for PDF tables, or Tika/Unstructured for free-text statements).
    * `normalize_rows(rows)` → map provider columns to canonical schema (`tx_date`, `amount`, `currency`, `description`, `transaction_type`, `category_name`, `upi_flag`, `raw_text`).
    * `categorize_transactions(rows)` → deterministic rules (regex, merchant mapping, UPI detection) + LLM for fuzzy matches.
    * `save_preview(upload_id, rows)` → store intermediate preview records in DB.
    * `notify_user(upload_id)` → push WebSocket/notification.

* **AI / LLM integration**

  * Rule-first approach: try deterministic rules (merchant mapping, keyword matching, regex for UPI ids).
  * If rules are low-confidence, call LLM (via LangChain) with a short prompt and a small batch of transactions for classification suggestions.
  * Save model suggestions and a confidence score for each transaction.

* **Storage**

  * Files: store original uploads in S3 (or a Docker volume `./uploads` for now).
  * Parsed preview: DB table `upload_transactions_preview`.
  * Final saved transactions: `transactions` table (already present) with `source_upload_id` metadata.

* **Security & Privacy**

  * Ensure uploads are stored encrypted at rest in production (S3 server-side encryption).
  * Limit file types & sizes; scan for malware if relevant.
  * Auth: only allow uploads tied to the authenticated user.

# Processing Pipeline (detailed)

1. **Upload** (user posts files)

   * Backend receives multipart request, creates an `uploads` row status=`uploaded`, stores original files on disk/S3, then enqueues `process_upload(upload_id)`.

2. **Parsing**

   * For **Excel**: Use `pandas.read_excel()` with heuristics (header row detection).
   * For **PDF**: Try table-extraction libraries:

     * If bank PDFs are tabular (many are), prefer `camelot` (requires Ghostscript) or `tabula-py` (Java). If unreliable, fallback to `pdfplumber` with heuristics (detect columns by whitespace).
     * For free-text PDFs (images or scanned): use OCR (Tesseract) + parsing (only if needed; heavy).
   * Normalize extracted rows into canonical fields.

3. **Normalization**

   * Clean date formats, unify debit/credit signs, deduce `transaction_type` (expense vs income) based on credit/debit or positive/negative amounts.
   * Detect currency from file or labels.
   * Extract UPI / VPA (regex like `\w+@\w+`) and set `upi_flag = True` when matched.

4. **Categorization (rules + LLM)**

   * First pass: merchant name map (configurable list). For example `PAYTM`, `AMAZON` → `Shopping`.
   * Regex rules: `ATM`, `FUEL`, `PAYMENT`, `GROCERY`, `UPI` hints.

### Code hints & snippets

* FastAPI endpoint (skeleton — drop into your `api/routes/uploads.py`):

```python
from fastapi import APIRouter, Depends, UploadFile, File, Form, HTTPException
from api.dependencies import get_db, get_current_user
import os, uuid
from infrastructure.db.postgres_repository import PostgresUploadRepository  # you will implement

router = APIRouter(prefix="/uploads", tags=["uploads"])

@router.post("/")
async def upload_statement(
    bank_name: str = Form(...),
    account_type: str = Form(...),
    statement_month: str = Form(...),
    files: list[UploadFile] = File(...),
    db = Depends(get_db),
    current_user = Depends(get_current_user),
):
    # create upload row in DB, get upload_id
    upload_repo = PostgresUploadRepository(db)
    upload = upload_repo.create_upload(user_id=current_user.id, bank_name=bank_name, account_type=account_type, statement_month=statement_month)
    upload_dir = f"./uploads/{current_user.id}/{upload.id}"
    os.makedirs(upload_dir, exist_ok=True)
    for f in files:
        path = os.path.join(upload_dir, f.filename)
        with open(path, "wb") as out:
            content = await f.read()
            out.write(content)
        upload_repo.add_file_record(upload.id, f.filename, path)
    # enqueue background job (or start background task)
    # e.g., celery.send_task("tasks.process_upload", args=[upload.id])
    return {"upload_id": upload.id, "status": upload.status}
```
